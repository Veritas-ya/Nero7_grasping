# 控制逻辑与感知延迟修复

本次修改针对连续状态机的放置、坐标和停止处理，以及实机反馈的 debug 卡顿、
测速失效和同一物块 ID 重建。软件回归与实际硬件验证必须分别记录。

## 控制行为

- 所有正式模式默认 execution_enabled=false。dry_run=true 也阻止全部运动/夹爪命令。
  bringup 和旧 dry_run launch 现在使用各包安装目录中的配置。
- 连续模式使用 calibration.yaml 中的 gripper_tcp、grasp_rpy 换算法兰位姿。
  网络抓取点沿带向运输到固定抓取线；不再追逐图像里的旧物体位置。
- 已选目标每步检查速度有效性和观测新鲜度，失效后不进行除法或下降。
  接近/等待/下降期间失效会停止并进入 HALT。连续模式也在反馈丢失、执行关闭、
  指令异常和进程退出时请求停止。
- 放置每段仅发送一次运动，等待运动开始/结束和夹爪释放反馈后才计成功。
  缺少 7 关节和 6 元素的示教放置配置会拒绝连续抓取，不能发送空列表。
- 静态模式把结果绑定到同一目标，异步执行 IK；执行前重查目标 XYZ、
  网络方向/宽度/点位、计划年龄和机械臂起始姿态。执行中关闭开关会停止。
  static_plan_max_age 默认 5 秒；开启/开爪期间继续检查目标和网络结果。
- 网络和检测器使用相同的畸变模型。网络输入必须是同网格、同光学系的注册 RGB-D；
  points 感知模式不能让控制器使用未注册的原始深度作为网络输入。

## 感知行为

相机回调仅缓冲帧，processing_rate_hz（默认 30）定时选择最新鲜且未使用过的
配对帧。输入 ROS 队列深度为 1，过时配对不逐帧追赶；时间戳仍为真实采集时间。
debug 默认最高 10 Hz、宽度 640；debug_max_width=0 可保留原尺寸。
这些限制只影响调试输出，不改变检测 ROI、相机内参或控制坐标。

旧带面 RANSAC 限制到 5000 个样本，避开小矩阵乘法的线程开销、自适应终止、
并对内点重拟合。三维带面高度系数按相机/变换/法向量缓存，变换变化会失效。

已确认 ID 按 tracker_lost_timeout（默认 0.5 秒）到期，未确认目标仍使用丢帧上限。
创新门限拒绝不会立即当成有效观测；仅唯一邻近对象在 3 个不同时间戳上呈现
一致、至多 20 mm 的中心偏移时才保留原 ID 重新初始化滤波器，旧速度资格作废。
相邻多物体存在歧义时不做这项重新关联。

测速观测窗口从 0.6 秒改为 1.2 秒，仍要求至少 8 次独立观测、0.3 秒跨度、
0.15 秒观测新鲜度以及原有速度协方差门限。相机停流不会被认定为有效测速。

## 实机验证

重建并重启所有相关进程：

```bash
colcon build --packages-select nero7_msgs nero7_perception nero7_control nero7_bringup
source install/setup.bash
```

先保持执行关闭，沿用现场已验证的相机外参、感知模式、ROI 和空带平面文件。
本次没有把默认 legacy_depth 自动切换到另一种需要重新标定的模式。

观察 /perception/diagnostics 的 processed_fps_window、process_ms、capture_age_ms、
backlog_frames_dropped 和 tracks_detail：
- 同一物体经过有效视野，ID 应持续保留；短时遮挡后检查是否仍为同一 ID。
- WAITING 时看 qualification_reason、accepted_recent 和 velocity_std_m_s，
  不要把无效速度的 0 当成静止实测值。
- reacquisitions 增加表示中心发生了一致偏移；应检查深度噪声、遮挡和 ROI。
- 处理耗时高、capture_age_ms 高或大量配对丢弃时，仍需检查现场 CPU 负载和驱动同步。

软件测试不能证明真实带速精度或运动抓取成功率。动态抓取仍需近期时序标定，
静态与连续模式的 TCP、工作区及放置位姿应在现场验证。

## 自动检查范围

GitHub Actions 编译全部 src Python 文件，运行不需要 ROS/机械臂的控制、预测、
跟踪、深度和显示回归。ROS 消息、驱动和完整硬件测试不在这个纯逻辑任务中；
原有 ROS 相关测试应在已构建的现场工作区另外执行。
